# Parity с `@z_ai/coding-helper`

`zai_python_helper` — **независимая clean-room реимплементация** наблюдаемого
поведения проприетарного `@z_ai/coding-helper` (npm) от Z.ai. Она **не делит** с
тем пакетом исходников — только *наблюдаемое поведение* того, как Claude Code
настраивается на разговор с GLM Coding Plan, reimplemented с нуля под MIT.

Мы отслеживаем паритет в **двух фазах**.

## Фаза 1 — строгий поведенческий паритет

Цель: пользователь, переходящий с `@z_ai/coding-helper` на `zai_python_helper`,
видит **идентичное наблюдаемое поведение**. Что клонируем точно:

- **ФОРМАТ `-v` / `--version`.** Голая строка версии без префикса имени программы,
  совпадающая с upstream. Сам *номер* версии отличается, поэтому тест
  нормализует только semver-токен; обе команды должны успешно завершаться и не
  писать в stderr.
- **Конфигурация Claude Code в original mode.** Headless-путь upstream
  `auth …` + `auth reload claude` и наш `use zai --mode original` сравниваются
  по normalized-JSON контракту: UTF-8 JSON парсится, фиксированный тестовый
  токен заменяется, затем объект сериализуется с сортировкой ключей. Значения,
  JSON-типы, порядок массивов и наличие ключей должны совпадать; whitespace,
  порядок ключей объектов и финальный перевод строки намеренно игнорируются.
- **Полный набор артефактов HOME** для этого потока. Docker-тест допускает лишь
  явные направленные исключения: upstream-only `.chelper/config.yaml` хранит
  plan/token; наши `.zshrc`, `.zai-python-helper/ownership.json` и
  `.zai-python-helper/lock` — Phase-2 артефакты ниже. Любой другой missing или
  extra файл валит parity.

Фаза 1 **строга**: рассинхрон — это баг, а не фича. Если оригинал делает X, мы
делаем X.

## Фаза 2 — наши расширения (рассинхрон допустим)

Когда Фаза 1 зафиксирована, мы наслаиваем расширения, которых у оригинала нет.
Здесь **рассинхрон допустим и намеренен** — мы больше не пытаемся повторить
оригинал, мы улучшаем его. Текущие расширения Фазы 2:

- **Импортируемое ядро.** Логика планирования — библиотека (`plan_zai`,
  `plan_default`, `postconditions`), а не только CLI. Оригинал — только CLI. См.
  [Импортируемое API](guide/importable.md).
- **Headless-работа.** Каждое действие — флаг CLI; никакого интерактивного меню.
  Оригинал ведёт интерактивный запрос.
- **Дополнительные model modes.** Для `default`, `select` и `custom` нет
  эквивалентной поверхности выбора модели в upstream 0.0.7, поэтому это наши
  расширения с локальными unit/integration-тестами. С upstream в Phase 1
  сравнивается только `original`.
- **Shell warning block.** Управляемый блок `.zshrc` обслуживает headless-first
  работу; сравниваемый upstream headless path не пишет shell rc-файл.
- **Журнал владения.** Обратимая, самоинвалидирующаяся семантика отката
  (ADR-004), хранящаяся в `.zai-python-helper/ownership.json`.
- **Многофайловая атомарная активация.** Валидируемый `PatchPlan`, применяемый
  под процессным локом с атомарными переименованиями (ADR-005); lock-файл —
  `.zai-python-helper/lock`.

## Как верифицируем Фазу 1

Docker-образ паритета собирает **оба** инструмента, а CI запускает полный
upstream parity-suite (см. `docker/parity/` и `tests/parity/`). Он снимает
снимок каждого regular file под fresh HOME, проверяет закрытые наборы артефактов
выше и normalized-JSON-диффит два общих Claude Code файла после redaction
токена. Если мы расходимся на поверхности Фазы 1 — CI краснеет.
